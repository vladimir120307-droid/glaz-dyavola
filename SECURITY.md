# Политика безопасности и область применения

## Скоуп — OSINT-разведка

`Глаз Дьявола` это **инструмент пассивной разведки и read-only валидации**, не атакующий фреймворк. Допустимые сценарии:

- Авторизованные red-team / bug-bounty / ASM-задания (есть RoE, in-scope актив, контракт)
- Threat intelligence / due-diligence / OSINT-журналистика по открытым источникам
- Собственная инфраструктура (что под вашим контролем — `whois`, IP-блок, домены)
- Защитная сторона: проверка собственной поверхности атаки, выявление утечек

## Что инструмент намеренно НЕ делает

- Активная эксплуатация уязвимостей, RCE-цепочки, payload-генерация
- Brute-force / credential stuffing / spray-атаки
- Post-exploitation (lateral movement, persistence, exfil)
- Malware / C2 / loader / dropper генерация
- Detection evasion (obfuscation, AMSI bypass, EDR-evasion)
- Массовое сканирование без авторизации

Если такой функционал нужен — `Глаз Дьявола` не тот инструмент. Используйте профильные фреймворки в авторизованной среде.

## Скоуп-проверка

Каждый модуль, обращающийся к внешнему хосту, должен явно получать цель от пользователя (через CLI-параметр, конфиг или MCP-tool-call). Инструмент не делает discovery самостоятельно вне указанных целей.

## Read-only валидаторы

Валидаторы кредов (AWS/GitHub/Slack/Anthropic/OpenAI/...) используют только эндпоинты вида `whoami` / `getCallerIdentity` / `auth.test` — они не модифицируют ничего. Любое расширение должно соблюдать это правило.
